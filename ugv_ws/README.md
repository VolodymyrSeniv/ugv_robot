# UGV 6x6 VSLAM — workspace

Autonomous 6x6 skid-steer UGV, no encoders: stereo visual odometry + IMU, RTAB-Map SLAM, Nav2.
Operator sends a goal on the map; the robot drives there and then returns to its start pose.

Status: **works in simulation** (headless Gazebo Fortress in Docker, arm64). Not yet tried on hardware.

## Run in simulation (Docker; tested with OrbStack on Apple Silicon)
```bash
cd docker && docker build -t ugv-ros2:humble .
cd .. && mkdir -p data
docker run -d --name ugv-sim \
  -v "$PWD/src:/ws/src" -v "$PWD/data:/ws/data" -v "$PWD/tools:/ws/tools" \
  -v ugv_build:/ws/build -v ugv_install:/ws/install -v ugv_log:/ws/log ugv-ros2:humble \
  bash -c "source /opt/ros/humble/setup.bash && cd /ws && colcon build --symlink-install && \
           source install/setup.bash && ros2 launch ugv_bringup autonomy.launch.py headless:=true"
# wait ~80 s, then send a goal (publish a few times: a single --once can be lost)
docker exec ugv-sim bash -c 'source /opt/ros/humble/setup.bash; ros2 topic pub -t 3 -r 2 /ugv/goal \
  geometry_msgs/msg/PoseStamped "{header: {frame_id: map}, pose: {position: {x: 3.0, y: 0.0}, orientation: {w: 1.0}}}"'
```
On Ubuntu with an NVIDIA GPU use `tools/run_sim_gui.sh` to get the Gazebo window: see [docs/UBUNTU.md](docs/UBUNTU.md).
Trace a run (true pose vs VO vs SLAM, CSV): `python3 tools/trace_run.py data/run.csv` inside the container.

## Layout
- `ugv_description` — xacro model (6 wheels, stereo pair, IMU), textured arena world, textures
- `ugv_localization` — EKF config (VO + IMU yaw rate)
- `ugv_navigation` — Nav2 params (generated by `tools/make_nav2_params.py`)
- `ugv_bringup` — `sim`, `slam`, `nav`, `autonomy` launch files
- `ugv_mission` — `mission_manager`: goal -> go -> return to start, with the localization-jump guard
- `ugv_ui` — operator web UI (rosbridge + one HTML page, no external libraries)
- `tools/` — generators (textures, worlds, Nav2 params), trial runners and series scripts, fault injector,
  plotting / video scripts (`plot_series.py`, `compare_series.py`, `make_video.py`)
- `docs/` — `RESULTS.md`, `figures/` (PNG plots per series), `videos/` (mp4 + gif of runs)

## Operator UI (laptop browser)
```bash
tools/run_sim.sh            # simulation + UI; or add `ui:=true` to any launch of autonomy.launch.py
# then open http://localhost:8080
```
Left-drag on the map sets a goal (drag direction = heading), **Go to goal, then return to start** sends it,
**Return home**, **Abort**, **Set start here** call the mission services. The page shows the map, robot,
trail, Nav2 path, start point, mission status and result, and a red banner after a localization jump.
It talks to rosbridge on port 9090, so it also works against the real robot (`http://<robot-ip>:8080`,
or `?host=<robot-ip>`). Needs no internet. Tested with a click-to-go mission in the simulation.

## Mission interface
- `/ugv/goal` (`geometry_msgs/PoseStamped`, frame `map`) — start a mission
- `/ugv/mission_status` (`std_msgs/String`) — IDLE / GOTO / RETURN / FAILED
- `/ugv/mission_result` (latched): `SUCCESS` / `COMPLETED_JUMP_DETECTED` / `ABORTED_LOCALIZATION_JUMP` / `ABORTED_GOAL_UNREACHABLE` / `FAILED: ...`
- `/ugv/start_pose` (latched), `/ugv/pose` (robot in map, for the UI)
- `/ugv/abort`, `/ugv/return_home`, `/ugv/set_start` (`std_srvs/Trigger`)

## Results
See [docs/RESULTS.md](docs/RESULTS.md): 16-trial series in simulation (goal error ~0.2 m, return error
~0.23 m, true-pose ATE ~0.05 m), and an injected-jump experiment showing the localization-jump guard
returns the robot home in 16/16 trials versus a cascade of failures without it.

Run a series: `tools/run_series.sh NAME WORLD GUARD [REPEATS]` (worlds: `test_world`,
`test_world_aliased`) or `tools/run_injection_series.sh NAME GUARD [REPEATS]` (needs the Mac/PC awake).

## Saved map
`tools/run_map_then_localize.sh NAME` maps (mapping mode), stops RTAB-Map with SIGINT so it writes
`data/maps/NAME.db`, then runs the same trials in localization mode. Interactively:
`tools/run_sim.sh localization /ws/data/maps/NAME.db`. The database is written only on a clean exit
(`docker exec ugv-sim pkill -INT -f "ros2 launch"`).

## Known issues / next steps
- Wheel friction was fixed (turns ~0.34 rad/s); a 180 deg turn still takes ~10 s.
- The guard sets `ABORTED_LOCALIZATION_JUMP` / `COMPLETED_JUMP_DETECTED` on `/ugv/mission_result`; only `SUCCESS` means a clean mission.
- Long exploratory tours fail: visual odometry gets lost and does not recover (docs/RESULTS.md, section C).
- Costmaps use only the RTAB-Map `/map`; no separate live obstacle layer yet.
- `/ground_truth/odom` is the simulator's true pose, for evaluation only. The wheel odometry
  from the DiffDrive plugin is NOT ground truth (wheels slip) and is discarded.
- Next: make the odometry robust on long runs (IMU-aided or visual-inertial pipeline), a live obstacle layer, real hardware (camera calibration, motor driver).
